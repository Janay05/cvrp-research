# Performance report history

Sequential log of performance investigations and reports for this solver. Each report is self-contained (states what changed since the previous one and what was measured); read them in order for the full history, or just the latest for current state.

- [001_p1_p4_filo2_baseline.md](001_p1_p4_filo2_baseline.md) — Initial investigation into the suspicious P=4 speedup claim. Root-caused the iteration-budget mismatch between P=1/P=4, fixed the stale `Num Routes` header and Stage 3 cost-bookkeeping drift, ran a real FILO2 baseline. Flagged (not fixed) a capacity-violation bug found under a stress-test iteration count.
- [002_capacity_fix_and_rebalance.md](002_capacity_fix_and_rebalance.md) — Root-caused and fixed the capacity-violation bug (missing route-info rescan in Stage 5). Rebalanced the P=4 iteration budget to give every thread the same absolute search budget as P=1. Re-measured against FILO2, found diminishing returns from more iterations alone, and lays out the next concrete steps (extend Stage 5/Stage 3 budgets) to close the remaining ~7% cost gap.
- [003_scale_testing.md](003_scale_testing.md) — Added a VRP file loader (the pipeline previously only ran on its own synthetic 2000-node instance) and fixed a memory-scaling bug this surfaced. Tested correctness/performance from 50 to ~1,000,000 customers: near-optimal at 50 nodes, and at 1M nodes the pipeline beats FILO2 by 2.4x on wall-clock while staying within 1.1% on cost. Found the report-002 iteration-budget formula doesn't generalize across scales and needs to become scale-aware next.
- [004_time_budget_scheduling.md](004_time_budget_scheduling.md) — Stress-tested the old iteration-budget mechanism harder before replacing it (no bugs found), then replaced it with wall-clock time budgets per stage (mirroring FILO2's own time-based cooling), which also fixed the per-thread timing imbalance from report 003 by construction. Used the new mechanism to tune cost: at 20k nodes, now 2.3x faster than FILO2 at +1.45% cost (beating the prior default on both axes); at 1M nodes, 3.87x faster at +1.10% cost. Found Stage 5's budget is the highest-leverage lever at small/medium scale but has muted returns at 1M nodes — flagged as still open.
